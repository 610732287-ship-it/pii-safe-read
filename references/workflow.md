# PII 安全读取工作流（pii-safe-read）

本文件说明整套「在不把个人敏感信息上传到 AI 服务端的前提下处理表格」的流程与边界。
适用于金山文档/多维表格(dbt)、xlsx，以及任何带字段结构的表格。

---

## 一、核心原则：不读取 = 不上传

只要 AI 代理**读取**了某一行/某一列，那些值就会作为对话内容传到模型服务端，
此时再在输出里「脱敏/打码」已经**晚了**——字节已经上去了。

因此唯一的硬防护是：**从请求源头就不取 PII 列**。即使用列作用域读取（见第三节），让数据源只返回安全列。

> 注意：换本地模型（如 Ollama）只能挡住「模型端」，挡不住云端连接器拉取数据这一环。
> 真正零上传 = 不读 PII 列，或整个走本地脚本 + 本地文件（不用云端连接器）。

---

## 二、生成安全读取清单（首次/换表时）

1. **只取字段结构，不取行数据。**
   对金山文档多维表格调用 `dbsheet.get_schema`（返回仅字段名/类型，不含行数据，零 PII 上传）。
   该工具会把结果写入 WorkBuddy 的 `tool-results` 目录下一个 `.txt` JSON 文件。
2. **跑生成脚本：**
   ```bash
   python scripts/gen_safe_list.py --schema 路径/到/schema.json --title 表名 --out 安全读取清单.md
   ```
   脚本读取 `references/pii_rules.json`（技能目录下）的规则，把每个字段分为 PII / 需确认 / 安全 三类，输出清单。
3. **抽查 + 调规则：** 打开清单，确认分类是否贴合本表命名。若新表有当前关键词未覆盖的列名，
   编辑 `pii_rules.json`（增删 `pii_kw` / `allow_kw` / `review_kw`），重跑脚本即可。规则按子串匹配（大小写不敏感）。
4. **交接给同事：** 把 `pii_rules.json` 一并分享，同事用自己的表重跑即可复用同一套判定。

---

## 三、安全读取数据（日常操作）

- ✅ 用 `records_list` / `list_records`，传 `fields` = 清单里**安全列的字段ID**（`prefer_id=true`）。
  WPS 只返回这些列，PII 列从请求到响应全程不参与 → 其值不进服务端。
- ❌ **禁用 `get_range_data`**：它返回矩形选区内**所有列**，会连带取出 PII 列并上传。
- ⚠️ 「需人工确认列」（备注类等自由文本）默认不读，除非确认其值不含手机号/身份证。
- 🔒 输出时仍默认对残留 PII 脱敏（双保险），但根本防护在「不取」这一环。

> 边界：此方案保护的是 **PII 列不出域**；安全列里的业务数据（来源渠道、缴费金额等）仍会经云端连接器中转，
> 这是使用云端工具（kdocs / qq-mail 等）的固有代价。「任何数据都不上服务器」需改走本地导出 + 本地脚本。

---

## 四、历史已上传 PII 的擦除（补救）

若过去某次会话已读取并上传了 PII（发生在设规则之前），清单无法撤回。需走平台方擦除：

- **服务端副本：** 向所用 AI 平台的官方隐私/数据删除邮箱发邮件，主题如
  `数据删除请求 / Data Erasure Request — 会话数据（日期 + 表名）`，正文引用隐私政策 Erasure 条款，
  要求删除该会话在服务端的所有副本（含 PII 字段明文）。
  注：远程副本通常按隐私政策有保留期限，到期自动清除；邮件可加速并确认擦除。
- **本地副本：** 在客户端左侧会话列表删除对应会话（注意：当前进行中的会话无法单独剥离，删除会结束本次对话）。
- **前置确认：** 删除本地会话前，先把安全读取清单与脚本备份到工作区之外，避免误删成果。

---

## 五、兜底纪律

清单 + 列作用域读取是**强流程、非硬防火墙**——依赖每次正确传 `fields`。任何一次漏传（返回全部字段），
PII 即上传。所以执行时务必对照清单，且优先用 `records_list` 而非 `get_range_data`。
